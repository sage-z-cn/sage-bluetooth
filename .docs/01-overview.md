# Sage Bluetooth - 开发设计文档

## 1. 项目概述

### 1.1 项目背景

本项目是一款面向 Windows 平台的蓝牙连接管理工具，采用 Python 开发，使用 PyQt5 构建 GUI，以 Bleak 库作为 BLE（Bluetooth Low Energy）操作核心。工具常驻系统托盘，通过点击托盘图标在屏幕右下角弹出 400x600 的工具小窗口，提供完整的蓝牙设备发现、配对、连接、断开及设备信息读取等功能。

### 1.2 目标平台

- **操作系统**：Windows 10/11（版本 16299 及以上）
- **Python 版本**：3.10+
- **蓝牙协议**：Bluetooth Low Energy (BLE / Bluetooth 4.0+)

### 1.3 核心功能

| 功能模块 | 功能描述 |
|---------|---------|
| 系统托盘 | 常驻托盘，左键点击弹出/隐藏主窗口，右键显示菜单 |
| 蓝牙开关 | 开启/关闭系统蓝牙适配器 |
| 设备扫描 | 刷新并列出附近可发现的 BLE 设备 |
| 设备配对 | 与目标 BLE 设备执行配对/绑定 |
| 设备连接 | 连接到已配对或广播中的 BLE 设备 |
| 设备断开 | 断开当前已连接的 BLE 设备 |
| 设备信息 | 读取设备名称、型号、厂商、电量等信息 |
| 设备类型识别 | 根据 Appearance 特征值和广播数据识别设备类型 |

### 1.4 技术栈

| 层级 | 技术选型 | 版本要求 |
|-----|---------|---------|
| GUI 框架 | PyQt5 | >= 5.15 |
| BLE 库 | bleak | >= 0.22 |
| 异步运行时 | asyncio (Python 标准库) | - |
| 打包工具 | PyInstaller | >= 6.0 |

## 4. 关键技术决策

### 4.1 为什么选用 Bleak？

| 候选库 | 优点 | 缺点 | 结论 |
|-------|------|------|------|
| **Bleak** | 纯 Python，跨平台，asyncio 原生，活跃维护 | Windows 依赖 WinRT | **选用** |
| pybluez | 经典蓝牙支持好 | BLE 支持弱，Windows 配置复杂 | 不适用 |
| bleak-py | 基于 Rust btleplug，性能更好 | 第三方维护，生态较小 | 备选 |
| windows.Devices.Bluetooth | 原生 WinRT API | 需 C++/C# 封装 | 过于底层 |

Bleak 是 Python BLE 领域的事实标准，提供统一的异步 API，Windows 后端基于 WinRT，无需额外驱动。

### 4.2 为什么选用 PyQt5？

| 候选方案 | 优点 | 缺点 | 结论 |
|---------|------|------|------|
| **PyQt5** | 功能完整，QSystemTrayIcon 成熟，QSS 样式丰富 | 体积较大 | **选用** |
| PySide6 | 官方 LGPL 授权，Qt6 新特性 | 系统托盘兼容性待验证 | 备选 |
| tkinter | Python 内置，轻量 | 托盘支持差，样式简陋 | 不适用 |
| PySimpleGUI | 简单快速 | 功能受限，托盘支持弱 | 不适用 |

PyQt5 的 `QSystemTrayIcon` 在 Windows 上表现稳定，社区资料丰富，适合工具类应用。

### 4.3 asyncio 与 PyQt 事件循环的整合

Bleak 基于 asyncio，PyQt 基于自己的事件循环。需要选择一个整合方案：

**方案 A：qasync（推荐）**
- 使用 `qasync` 库将 asyncio 事件循环与 Qt 事件循环整合
- 允许在 Qt 槽函数中直接使用 `async/await`
- 代码最简洁，维护性最好

**方案 B：手动线程桥接**
- 在后台线程中运行 asyncio 事件循环
- 通过信号/槽与 Qt 主线程通信
- 无需额外依赖，但代码复杂度较高

**推荐方案 A**，`qasync` 是社区验证的成熟方案。

### 4.4 蓝牙适配器开关的实现

Bleak 本身不提供蓝牙适配器电源控制 API。Windows 上需要通过以下方式实现：

**方案 A：PowerShell PnP 命令（推荐）**
```powershell
# 开启蓝牙
Enable-PnpDevice -InstanceId $(Get-PnpDevice -Class Bluetooth | Select-Object -First 1).InstanceId -Confirm:$false
# 关闭蓝牙
Disable-PnpDevice -InstanceId $(Get-PnpDevice -Class Bluetooth | Select-Object -First 1).InstanceId -Confirm:$false
```

**方案 B：Windows Runtime API**
- 通过 `winrt` 库调用 `Windows.Devices.Radios.Radio`
- 更优雅，但需要额外依赖

**推荐方案 A**，通过 Python `subprocess` 调用 PowerShell，实现简单可靠。

> ⚠️ **注意**：开关蓝牙适配器需要管理员权限。设计时应检测权限并给出友好提示。

## 6. 风险与限制

### 6.1 已知限制

| 限制项 | 说明 | 缓解方案 |
|-------|------|---------|
| 仅支持 BLE | Bleak 只支持 Bluetooth Low Energy，不支持经典蓝牙 (BR/EDR) | 文档明确说明，未来可考虑集成 pybluez |
| Windows 版本要求 | 需 Windows 10 版本 16299+ | 安装时检测系统版本 |
| 蓝牙开关需管理员权限 | PowerShell PnP 命令需要管理员权限 | 运行时检测权限，引导用户以管理员身份运行 |
| 电量读取依赖设备支持 | 并非所有 BLE 设备都实现了 Battery Service | 友好提示"设备未提供电量信息" |
| 设备类型识别不完全准确 | Appearance 特征值可能缺失或为通用值 | 结合广播数据中的服务 UUID 辅助判断 |

### 6.2 潜在风险

| 风险 | 影响 | 应对策略 |
|-----|------|---------|
| Bleak 版本升级 API 变更 | 兼容性问题 | 锁定 requirements.txt 中 bleak 版本范围 |
| WinRT 后端稳定性 | 偶发连接断开 | 实现自动重连机制，记录日志 |
| 多设备并发连接 | Bleak 对并发支持有限 | 设计为单设备连接模式，连接新设备时先断开旧设备 |
